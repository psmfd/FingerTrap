What is implemented and verified

Pi’s opt-in --startup-policy managed-v1 validates explicit inputs before command dispatch or migration, constructs in-memory settings/auth/model configuration, and loads only explicitly selected extension files with a literal system prompt. Reload and supported new-session operations retain that policy. Unsupported configuration, installation, authentication and session transitions fail with bounded errors.

FingerTrap descriptor v2 requires that policy and independently selected source revision and digest. Both transports use the same launch resolver. A separate published qualification executable compiles the production entry point and services with a test-only selection loader; production compilation has no managed selector.

Limits that remain explicit

  • Only macOS ARM64 managed executable artifacts have been exercised. Linux/Windows source CI does not qualify their Pi binaries.
  • The published qualification host shares the real entry point, services and native PTY path. It is a separate test build; production managed composition remains absent.
  • Managed startup is a resource-discovery contract, not an OS sandbox. Explicitly trusted extensions and tools retain their own filesystem/network authority.
  • Credentials, approvals, resume/import/cwd changes, stores/meters, complete extension imports and end-to-end activation still belong to later migration slices.
  • The binary and archive are unpublished local qualification outputs. No new release, production distribution, SDK adoption or operator installation was performed.
